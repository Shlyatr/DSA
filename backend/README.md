# Jana Address — разбор и нормализация адресов Казахстана

Решение кейса **Challenge 01 / Jana Address** (Jana Post Terricon Valley Hackathon 2026).

Превращает произвольную текстовую строку адреса (RU/KZ, латиница, слитно, с опечатками)
в структурированные поля по спецификации ТЗ. Работает **полностью локально, без внешних API
и без интернет-зависимостей на этапе разбора**.

> Текущий статус: готов **парсинг-ядро** (шаги 1–4 из 6). REST API, справочник,
> веб-UI и Docker — в дорожной карте ниже (см. [TODO](#todo--дорожная-карта)).

## Быстрый старт

Требуется **Node.js ≥ 18** (проверено на Node 22). Внешних зависимостей нет.

```bash
# 1. Тесты (34 шт., включая примеры из ТЗ и краевые случаи)
npm test

# 2. Разбор одной строки
node src/repl.js "ул. Абая 33/1 кв 12а"

# 3. Интерактивный REPL (ввод построчно, команды .help / .exit)
npm run repl

# 4. Пакетный разбор файла (JSON-массив, одиночный объект или JSONL)
npm run parse -- data/sample_input.json -o data/sample_output.json

# 5. Разбор всех примеров краевых случаев из ТЗ
node src/repl.js < data/examples.txt
```

### Пример

```
$ node src/repl.js "город Актобе/Ақтөбе қаласы, улица Абая 12"
{
  "province": "Актюбинская область",
  "city": "Актобе",
  "district": null,
  "living_area": null,
  "street_type": "улица",
  "street_name": "Абая",
  "house": "12",
  "apartment": null,
  "entrance": null,
  "floor": null,
  "landmark": null,
  "confidence": 0.89
}
```

CLI принимает JSON-массив, одиночный объект или JSONL; исходную строку берёт из полей
`raw_address | address | raw | address_str`. В выходных записях сохраняются `id` и
`raw_address` без изменений (требование ТЗ: пропускать записи запрещено).

## Архитектура

Разбор — это **детерминированный rule-based пайплайн** без ML и без сети. Порядок шагов
важен: сначала извлекаются «однозначные» поля, затем остаток очищается и только потом
ищутся улица, дом и ориентир.

```
parseAddress(raw)
  │
  ├─ normalize()             NFKC, невидимые символы, тире/кавычки, опечатки маркеров
  ├─ resolveBilingual()      «Актобе/Ақтөбе қаласы» → русская половина
  │
  ├─ house        ← «12дом», «12 дом», «д. 12»
  ├─ apartment    ← «69квартира», «кв 12а», «flat 191», «kv 12»
  ├─ entrance     ← «4подъезд» / «подъезд 4» (и опечатки «подьезд»)
  ├─ floor        ← «9этаж», «қабат 9», «floor 9»
  │
  ├─ province     ← «Туркестан облысы» → «Туркестанская область»
  ├─ district     ← «Ауэзовский район», «Сарыагаш ауданы»
  ├─ city         ← маркер «город/г./қала» + справочник синонимов (RU/KZ/латиница)
  │
  ├─ stripParticles()        удаление служебных слов
  ├─ splitGluedWordNumber()  «Назарбаева8» → «Назарбаева 8»; «66квартал» → «66 квартал»
  ├─ extractStreets()        ул./пр./кв./мкр/ЖК + улица без типа; номер дома после названия
  ├─ bare house              первый оставшийся номер дома
  │
  ├─ assembleLandmark()      ориентир, только если начинается с узнаваемого слова
  └─ computeConfidence()     эвристическая оценка 0..1
```

Ключевые инженерные решения:

- **`\b` не работает для кириллицы** в JavaScript, поэтому везде используются явные
  классы-ограничители `(?<![LETTER])` / `(?![LETTER])` (см. `lexicon.js: LETTER`).
- **Удаление найденных сущностей через битовую маску** по исходной строке, а не по
  индексам мутирующей строки — иначе наложения «съедают» не то.
- **`street_name` сохраняется как в строке** (падеж и опечатки не исправляются) —
  требование метрики.
- **Двуязычие**: если одна половина склейки содержит казахские буквы `әғқңөұүһі`,
  оставляется русская половина (`normalize.js`).

### Справочники в `lexicon.js`

| Сущность | Назначение |
| :--- | :--- |
| `STREET_DEFS` | 14 типов улиц (`street` / `micro` / `living`) с обеих сторон и всех языков |
| `CITY_ROWS` / `CITY_MAP` / `CITY_ALIASES` | ~70 городов + синонимы (каз., латиница, исторические) |
| `REPUBLICAN_CITIES` | Алматы / Астана / Шымкент → `province` = город |
| `STABLE_CITY_PROVINCE` | города с однозначной областью (для восстановления `province`) |
| `ADMIN_PARTICLES`, `STOP_TOKENS`, `STRAY_TOKENS` | служебные слова |
| `LANDMARK_PREFIXES` | маркеры ориентиров (`магазин`, `БЦ`, `Qazpost`, `ТРЦ`…) |
| `PROVINCE_CANON` | канонизация областей (`түркістан` → `Туркестанская`) |

## Формат полей

| Поле | Тип | Правило |
| :--- | :--- | :--- |
| `id` | string\|null | из входной записи, без изменений |
| `raw_address` | string | исходная строка, без изменений |
| `province` | string\|null | область / город респ. значения (`"Актюбинская область"`, `"Алматы"`) |
| `city` | string\|null | без «город», «пос.», без казахской половины при склейке |
| `district` | string\|null | без слова «район» (в автоматическую метрику входят только «строка содержит район») |
| `living_area` | string\|null | микрорайон/ЖК, если улица указана отдельно |
| `street_type` | string\|null | `улица / проспект / микрорайон / переулок / квартал` (в метрику не входит) |
| `street_name` | string\|null | название без типа, ровно как в строке |
| `house` | string\|null | с дробью и литерой (`"1/2"`, `"12а"`) |
| `apartment` | string\|null | только номер |
| `entrance` | string\|null | только номер |
| `floor` | string\|null | только номер |
| `landmark` | string\|null | ориентир из строки |
| `confidence` | number | 0..1, эвристика (в авто-метрику не входит, смотрит жюри) |

Неопределённое поле = `null`.

## Ограничения

- **Строка = один адрес.** Если склеить несколько адресов через запятую (несколько улиц
  и домов), выбирается один (приоритет — улица с явным типом `ул./пр.`), остальное
  отбрасывается. Это осознанно: ТЗ описывает «одну строку = один адрес».
- **`district`/`living_area` восстанавливаются только из строки.** Подъём из справочника
  (OSM/КАТО) — отдельный этап (Инженерный критерий 30%), см. TODO.
- **`province`** восстанавливается из города только для `STABLE_CITY_PROVINCE`
  (однозначные регионы, не затронутые реформой 2022 г.). Для остальных — `null`, если нет в строке.
- **`landmark`** сохраняется только если начинается с известного маркера
  (`магазин`, `БЦ`, `Qazpost`…), чтобы произвольный мусор не попадал в поле.

## Как работает разбор (v2)

`src/parser.js` — конвейер из 8 шагов:

1. **normalize** — невидимые символы, пробелы, двуязычные склейки (`Актобе/Ақтөбе қаласы` → `Актобе`).
2. **tokenize** — слова / числа / разделители. Запоминается, был ли номер *приклеен* к слову (`4подьезд`, `кв5`) — от этого зависит, чьё это число.
3. **ориентир** — `магазин береке`, `Qazpost Солнечный`.
4. **квартира / подъезд / этаж / дом** — маркеры в обоих порядках: `4подьезд 9этаж`, `5 подъезд 239 кв` (число перед маркером) и `подъезд 3, этаж 5, кв 78` (после).
5. **улица** — по типу (`ул`, `пр`, `мкр`, `квартал`, `ЖК`, `көшесі`, `даңғылы`...). Номер дома сразу после названия улицы — дом; номер в названии микрорайона (`Айнабулак 4, дом 12`) — часть названия.
6. **область / район / город** — по маркерам и справочнику городов.
7. **остатки** — улица без типа (`Туран 55/6`), голый номер дома (`, 59,`), город без маркера.
8. **справочник** — район, область и тип улицы, которых нет в строке.

### Восстановление района по справочнику

Район в строке указан → берётся как написано, без слова «район» (`Ауэзовский`).
Иначе ищем по порядку (`src/dictionary.js`, `meta.sources.district` говорит, что сработало):

| Источник | Когда срабатывает |
|---|---|
| `reference:street(unique)` | улица (в этом городе) лежит ровно в одном районе |
| `reference:street(majority)` | ≥60% сегментов улицы в одном районе (тип улицы сужает выбор) |
| `reference:street(guess)` | города в строке нет, улица есть в 2–3 городах, один из них ≥3× крупнее |
| `reference:living_area` | по названию микрорайона / ЖК |
| `reference:city` | небольшой населённый пункт целиком лежит в одном районе |

Если улица в большом городе проходит через несколько районов поровну (`Алматы, ул. Абая`) — район остаётся `null`, а не выдумывается.
Числовые названия без города (`66квартал`) в справочнике не ищутся.

Названия районов в OSM казахские (`Қарасай ауданы`) — они переводятся в русские формы
(`Карасайский`): сначала по `districts.json` (`name_ru`), затем по правилам транслитерации + таблице исключений
(`dictionary.js → generateDistrictRu`). Городские администрации (`Қарағанды Қ.Ә.`) районами не считаются.

### Что сознательно не «исправляется»

Падежи и опечатки в названии улицы сохраняются как в строке (`казибек би`, `Аксай За`) — так требует ТЗ.

### API

- `POST /api/parse` — `{ "id": "...", "raw_address": "..." }` → `{ "result": {...} }`
- `POST /api/parse/batch` — массив записей → массив `{...запись, result: {...}}`;
  `?format=flat` — плоский массив в формате ТЗ (`sample_output.json`).
- Любой из методов с `?explain=1` (`/api/parse`) вернёт ещё `meta.sources` — откуда взято поле.

Скорость: ~60 мс на 1000 записей, загрузка справочника при старте ~1 с.
